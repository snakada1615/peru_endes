# 問題解決手順

以下は Quarto から PDF レンダリング時に R コード中のダブルクォートがバッククォートに変換され、LaTeX コンパイルエラーが発生した問題の解決手順です。

------------------------------------------------------------------------

## 1. 問題の確認

-   Quarto で次のような R コードを実行した際に PDF レンダリングエラーが発生。

    ``` r
    cat("\n=== 分析完了 ===\n")
    cat("主要結果:\n")
    cat("1. LASSO選択変数数:", length(selected_vars), "\n")
    ```

-   出力される `.tex` ファイルではダブルクォート (`"`) がバッククォート (\`\`\`\`) に置換され、LaTeX が「Undefined control sequence」としてエラー

## 2. 原因特定

-   Quarto の LaTeX 処理パイプラインにおける**ダブルクォート→バッククォート変換のバグ**
-   `cat()`, `sprintf()`, `message()` など複数の関数で同様の変換が発生

## 3. 試した対策

1.  **Raw 文字列リテラル**（R 4.0+）
2.  **`sprintf()`** を利用
3.  **Quarto チャンクオプション** の変更 (`results='asis'`, `echo=FALSE`)
4.  **シングルクォート** を利用
5.  **Quarto のアップデート** とコマンドラインレンダー (`quarto render`)

→ いずれもバッククォートへの変換を回避できず

## 4. 最終的な解決策

### writeLines()を利用

R コード中の文字列を全てwriteLines()に置き換えることで、Quarto がバッククォートに変換しないように回避。

``` r
writeLines(c(
  "=== 分析完了 ===",
  "主要結果:",
  paste("1. LASSO選択変数数:", length(selected_vars)),
  paste("2. 最終分析サンプル数:", nrow(df_post)),
  "3. 群別サンプル数:"
  )
)
print(table(df_post$treatment_group))
```

この方法で PDF が正常に生成され、LaTeX コンパイルエラーが解消されました。
